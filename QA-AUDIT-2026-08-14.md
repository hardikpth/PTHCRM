# PTH CRM Functional Audit — 14 August 2026

## Scope

Reviewed routing, create/edit/delete flows, local persistence, filtered registers, reload behaviour, imports, role-based record visibility, and runtime errors across Overview, Pipeline, CRM Intelligence, Daily Workspace, Follow-ups, Enquiries, Quotations, SOR, Clients, Tenders, Credentials, Scope, Analytics, Users, Audit Trail, and Settings.

## Confirmed defects fixed

1. A saved quotation could be hidden by a status or validity filter retained from an earlier visit. Saving now resets quotation filters before opening the register.
2. Newly created records could be hidden behind stale filters in Follow-ups, Enquiries, Clients, Credentials, and Tenders. Create flows now reset their module filters.
3. User add/edit/enable/disable/delete changes did not survive a page reload. Users are now stored and restored from browser storage.
4. Branding product name, company, logo, tagline, and accent did not survive a page reload. Branding is now stored and restored.
5. The credential form could have an empty Responsible Person list when the staff dataset was empty. Active application users are now included.
6. PDF-created Credential records were displayed but not persisted. They are now saved to the credential repository.
7. PDF-created Accreditation Scope records were displayed but not persisted. A dedicated persisted scope store was added.
8. The Enquiries register did not apply the same role-based record visibility rule used by Pipeline and global search. It now uses the shared visibility rule.

## Deployment note

The application is a static GitHub Pages app and stores operational data in the current browser's local storage. Records persist across reloads in that browser, but do not synchronize automatically to another computer, browser profile, or device. Shared multi-user synchronization requires a hosted database and authenticated backend.
